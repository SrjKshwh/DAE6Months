Containment Playbook

Automated containment procedures for incident response
Playbook Overview

This containment playbook provides automated procedures for isolating affected systems, preventing threat spread, and securing the environment during incident response operations.

Containment Phases

Phase 1: Immediate Containment (0-15 minutes)
Network Isolation
  • Firewall Rules: Block all inbound/outbound traffic from affected systems
    Execute: iptables -A INPUT -s [IP] -j DROP
  • Network Segmentation: Move affected systems to quarantine VLAN
    Isolate from production network segments
  • Service Disruption: Disable compromised services
    Stop affected applications and services
System Isolation
  • Account Lockout: Disable compromised user accounts
    Prevent lateral movement within the environment
  • Process Termination: Kill suspicious processes
    Stop malware execution and persistence mechanisms
  • Backup Isolation: Quarantine system backups
    Prevent reinfection from backup sources
Phase 2: Evidence Preservation (15-60 minutes)
Memory Acquisition
  • Live Memory Dump: Capture volatile memory
    Use Volatility or LiME for memory forensics
  • Process Memory: Dump suspicious process memory
    Capture running malware in memory
System State Capture
  • Network Connections: Log all active connections
    Document C2 communications and data exfiltration
  • File System Snapshot: Create disk image
    Preserve file system state for analysis
Phase 3: Threat Eradication (1-4 hours)
Malware Removal
  • Signature-based Scan: Run antivirus/malware scanners
    Remove known malicious files and registry entries
  • Rootkit Detection: Scan for hidden malware
    Use specialized tools to detect kernel-level threats
System Cleanup
  • Registry Cleanup: Remove persistence mechanisms
    Clean startup entries and scheduled tasks
  • Configuration Reset: Restore system configurations
    Reset to known good state where possible
Phase 4: Recovery and Monitoring (4+ hours)
System Recovery
  • Service Restoration: Gradually restore services
    Monitor for signs of reinfection
  • Network Reconnection: Reintegrate into production
    Verify security controls are active
Enhanced Monitoring
  • IDS/IPS Activation: Enable advanced threat detection
    Monitor for similar attack patterns
  • Log Analysis: Continuous security monitoring
    Establish baseline and detect anomalies

Automated Containment Scripts

⚠️ Warning: These scripts should be tested in a non-production environment before use. Always backup systems before automated containment.
Network Isolation Script
#!/bin/bash
# Automated Network Containment
# Usage: ./network_isolate.sh [target_ip] [case_number]

TARGET_IP=$1
CASE_NUMBER=$2

echo "[$(date)] Starting network isolation for $TARGET_IP"

# Block all traffic to/from target
iptables -A INPUT -s $TARGET_IP -j DROP
iptables -A OUTPUT -d $TARGET_IP -j DROP

# Log the action
echo "[$(date)] Network isolation complete for case $CASE_NUMBER" >> /var/log/containment.log
Process Termination Script
#!/bin/bash
# Automated Process Containment
# Usage: ./process_kill.sh [process_name] [case_number]

PROCESS_NAME=$1
CASE_NUMBER=$2

echo "[$(date)] Starting process termination for $PROCESS_NAME"

# Find and kill suspicious processes
pkill -f "$PROCESS_NAME"

# Log the action
echo "[$(date)] Process termination complete for case $CASE_NUMBER" >> /var/log/containment.log
