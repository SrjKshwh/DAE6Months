Root Cause Analysis Methodologies
5-Whys Analysis

A simple but effective method for uncovering the root cause of a problem by asking "why" five times.

Example: Ransomware Incident
  1. Why: Files were encrypted by ransomware
  2. Why: Malicious software executed on the system
  3. Why: User opened a malicious email attachment
  4. Why: Email bypassed security filters
  5. Why: Security policies not properly configured
Root Cause: Insufficient email security policy configuration
Fishbone Diagram (Ishikawa)

A cause-and-effect diagram that categorizes potential causes of a problem.

People:
  • Lack of training
  • Human error
  • Insufficient staffing
Process:
  • Weak procedures
  • No oversight
  • Poor documentation
Technology:
  • Outdated software
  • Configuration errors
  • Hardware failures
Environment:
  • Physical security
  • Network issues
  • External factors
Technical Analysis Framework

  • Log analysis (system, application, security)
  • Memory forensics (Volatility analysis)
  • Network traffic analysis (Wireshark)
  • File system analysis (timeline, artifacts)
  • Registry analysis (Windows systems)

  • Static analysis (signatures, strings, disassembly)
  • Dynamic analysis (sandbox execution)
  • Behavioral analysis (API calls, network activity)
  • Code analysis (decompilation, reverse engineering)
Analysis Best Practices
Do's
  • Preserve evidence chain of custody
  • Use multiple analysis methods
  • Document all findings thoroughly
  • Involve cross-functional team
  • Consider both technical and human factors
Don'ts
  • Jump to conclusions without evidence
  • Focus only on technical causes
  • Ignore contributing factors
  • Delay analysis for too long
  • Work in isolation
