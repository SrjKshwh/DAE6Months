# Incident Reporting Guide

## Overview
This guide provides step-by-step instructions for reporting security incidents in the GRC Portal. Following this process ensures timely response and proper documentation of security events.

## Prerequisites
- Valid user account with login access
- Clear understanding of the incident details
- Access to relevant evidence or logs

## Step-by-Step Incident Reporting Process

### Step 1: Access Incident Reporting
1. Log into the GRC Portal with your credentials
2. Navigate to the main menu
3. Click on "Report Incident" or access `/report_incident`
4. Verify you are on the incident reporting page

### Step 2: Gather Incident Information
Before reporting, collect the following information:
- **Date and Time**: When did the incident occur?
- **Systems Affected**: Which systems, applications, or data were impacted?
- **Incident Description**: What happened? Include specific details
- **Potential Impact**: What could be the consequences?
- **Evidence**: Screenshots, logs, or other supporting information

### Step 3: Complete the Incident Report Form
Fill out all required fields:

**Title Field:**
- Provide a concise, descriptive title
- Example: "Unauthorized Access Attempt Detected"
- Example: "Suspicious File Upload from External IP"

**Description Field:**
- Provide detailed account of the incident
- Include what you observed, when it occurred, and how you detected it
- Mention any error messages, unusual behavior, or security alerts
- Describe the scope and potential impact

**Severity Selection:**
Choose the appropriate severity level:
- **Low**: Minor issue with limited impact
- **Medium**: Moderate disruption or potential risk
- **High**: Significant security concern requiring immediate attention
- **Critical**: Major breach or system compromise

### Step 4: Submit the Report
1. Review all entered information for accuracy
2. Click the "Report Incident" button
3. You will receive a confirmation message
4. Note the incident ID for future reference

### Step 5: Monitor Incident Progress
1. Access the "Incidents" page to view your reported incidents
2. Monitor the status updates:
   - **Identified**: Initial report received
   - **Containment**: Incident isolation in progress
   - **Eradication**: Threat removal ongoing
   - **Recovery**: System restoration
   - **Closed**: Incident resolved

### Step 6: Provide Additional Information
If requested by the security team:
1. Respond promptly to follow-up questions
2. Provide additional evidence or context
3. Update incident details through the incident management interface

## Incident Response Framework

The GRC Portal follows a structured 5-step Incident Response Plan:

### 1. Preparation
- Security tools and procedures are in place
- Staff training on incident reporting
- Regular security assessments conducted

### 2. Identification
- Automated monitoring detects potential incidents
- User reports through this system
- Security alerts from various sources

### 3. Containment
- Isolate affected systems to prevent spread
- Implement temporary security measures
- Preserve evidence for investigation

### 4. Eradication
- Remove root cause of the incident
- Clean affected systems
- Patch vulnerabilities

### 5. Recovery
- Restore systems to normal operation
- Validate system integrity
- Monitor for reoccurrence

## Evidence Collection

When reporting incidents, consider collecting:
- **System Logs**: Application and security logs
- **Network Logs**: Firewall and access logs
- **Screenshots**: Visual evidence of the incident
- **Configuration Files**: Relevant system configurations
- **Timestamps**: Exact timing of events

## Communication Guidelines

### What to Report
- Any suspected security incidents
- Unusual system behavior
- Failed security controls
- Unauthorized access attempts
- Data breaches or exposures

### What NOT to Report
- General technical issues (use support channels)
- Performance problems unrelated to security
- Feature requests or enhancements

### Response Times
- **Critical**: Response within 1 hour
- **High**: Response within 4 hours
- **Medium**: Response within 24 hours
- **Low**: Response within 48 hours

## Post-Incident Activities

After incident resolution:
1. Review the final incident report
2. Participate in lessons learned sessions
3. Implement recommended security improvements
4. Update personal security awareness
